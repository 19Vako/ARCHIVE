# ARCHIVE


## Короткий огляд
**Назва проєкту:** ARCHIVE  
**Коротко:** SPA на React + TypeScript (create-react-app) для роботи з архівними картками/документами (UI для додавання, фільтрації, перегляду та затвердження документів).  
Проєкт - фронтендова частина; бекенд не включено в цей репозиторій (використовуються HTTP-запити через axios або react-query).



## Технологічний стек
- React 18  
- TypeScript  
- Create React App (react-scripts)  
- react-router-dom v6 - маршрутизація  
- axios - HTTP-клієнт  
- @tanstack/react-query - кешування/запити  
- react-infinite-scroll-component - безкінечний скрол  
- Cypress / Jest / Testing Library - тестування (devDependencies)  
- Prettier - форматування  



## Швидкий старт

### Передумови
- Node.js v16+ (рекомендується)

### Встановити залежності
- npm ci
- Запуск в режимі розробки
- npm start
- Відкрий http://localhost:3000.
- Збірка production
- npm run build
- Побудована папка — build (за замовчуванням для CRA). У package.json встановлений homepage — варто перевірити, чи потрібен цей шлях при деплої.



## Скрипти (package.json)
- start — запускає dev сервер (react-scripts start)
- build — продакшн збірка (react-scripts build)
- test — запуск тестів

    ### AddCardForm.tsx

    - Компонент який містить поля для вводу даних пристворенні 
      карток документу або додаток
    - Функції: 
      - handleFileChoose: 
        Функція **handleFileChoose** обробляє вибір файлу користувачем через елемент **<input type="file">**. Вона перевіряє, чи був обраний файл, після чого створює **FileReader** для зчитування цього файлу у форматі **Data URL base64**. Коли зчитування завершене, **Data URL** зберігається у стані **pdfURL**, а також зберігаються назва файлу **fileName** та сам файл **file** у відповідних станах для подальшого використання. Фактично, функція дозволяє відобразити файл у додатку та підготувати його для можливого завантаження або обробки.
      - handleChange:
        Функція **handleChange** обробляє зміни значень у полях форми **<input>**, **<textarea>** або **<select>**. Вона отримує ім’я поля та його нове значення і оновлює стан форми **formData**. Для полів дати **docCreateDate**, **docSigningDate**, **validityPeriod** функція переформатовує значення з **YYYY-MM-DD** у **DD-MM-YYYY**. Для всіх інших полів значення зберігається без змін. Таким чином, функція забезпечує динамічне оновлення стану форми відповідно до введених користувачем даних.
      - openAddDataModal:
        Функція **openAddDataModal** керує відкриттям або закриттям модального вікна для додавання даних. Вона приймає два параметри: **name** і **titleName**, які зберігаються у стані для використання всередині модального вікна. Потім функція перемикає стан **openDataModal**: якщо модальне вікно відкрите, його закриває, а якщо закрите — відкриває.
      - openApproveModal: 
        Функція **openApproveModal** керує відображенням модального вікна підтвердження. Вона перевіряє, чи є обраний файл **fileName**. Якщо файл існує, відкриває модальне вікно підтвердження **showApproveModal** і вимикає лог повідомлення про відсутність файлу **fileLog**. Якщо файл не вибрано, включає повідомлення про відсутній файл **fileLog**.
    - Інтерфейс: 
      поля для вводу:  
      **Тип Документа** 
      **Дата створення** 
      **Дата підписання** 
      **Срок дії** 
      **Найменування**

      **Код ЄДРПОУ контрагента**
      **Тип Договору**
      **Особистий номер**
      **Найменування контрагенту**
      **Вибір файлу**
      **Короткий зміст**

    ### AddAddition.tsx

    - Функції: 
      - GetAdditions: 
        Функція **GetAdditions** асинхронно отримує додаткові дані для документа за його ідентифікатором **_id**. Вона відправляє POST-запит на сервер за вказаним **URL**, передаючи **docId**. Якщо запит успішний, отримані дані зберігаються у стані **additions**. У разі помилки функція виводить повідомлення про помилку у консоль.
      - addAddition: 
        Функція **addAddition** асинхронно додає додатковий документ до основного за його ідентифікатором. Вона надсилає POST-запит на сервер із **docId** основного документа та additionDocId додаткового. Якщо запит успішний, функція закриває модальне вікно додавання **setShowAddAddition** і викликає **GetAdditions** для оновлення списку додатків. У разі помилки виводить повідомлення про помилку в консоль і зберігає текст помилки у стані **setAddAdditionLog**.
      -
    - Props: **cardId**
    - Інтерфейс: 
      **AddAddition** містить кнопки для додавання або скасування додаткового документа, список уже доданих посилань, блок з детальною інформацією про обраний документ, поле з коротким змістом та вбудований переглядач **PDF**.

    ### AddManager.tsx

    - Прив’язка менеджера до картки або 
    - Функції: 
      - getManagers: 
        **getManagers** отримує список менеджерів із сервера через POST-запит та зберігає його у стані setManagers.
      - FindManager:  
        **FindManager** виконує пошук менеджера за введеним ім’ям та оновлює стан списку менеджерів або повідомлення про помилку.
      - CleanInput: 
        Функція **CleanInput** очищає значення пошукового поля **setFindName**, викликає оновлення списку менеджерів через **getManagers** та скидає повідомлення про помилку **setFindError**.
      - AddManager:
        Функція **AddManager** надсилає POST-запит для додавання нового менеджера з вказаними ім’ям та паролем. Якщо запит успішний, зберігає повідомлення від сервера **setLog**, оновлює список менеджерів через **getManagers** та вимикає індикатор помилки **setLogError**. У разі помилки зберігає текст помилки **setLog** і вмикає індикатор помилки **setLogError**.
      - ChangeManager:
        Функція **ChangeManager** надсилає POST-запит для зміни даних менеджера за його **ID**, оновлюючи ім’я та пароль. Якщо запит успішний, оновлює список менеджерів через **getManagers**, вимикає індикатор помилки **setOptionsLogError** та зберігає повідомлення від сервера **setOptionsLog**. У разі помилки вмикає індикатор помилки **setOptionsLogError** і зберігає текст помилки **setOptionsLog**.
      - DeleteManager:
        Функція **DeleteManager** закриває модальні вікна видалення та перегляду менеджера, надсилає POST-запит для видалення менеджера за його **ID**, а після успішного видалення оновлює стан списку менеджерів **setManagers**, видаляючи відповідного менеджера.
      - DeletModal:
        Функція **DeletModal** відображає модальне вікно підтвердження видалення менеджера, якщо стан **deleteManagerModal** активний. Вікно містить повідомлення про підтвердження та дві кнопки: **Видалити**, яка викликає функцію **DeleteManager**, та **Відмінити**, яка закриває модальне вікно **setDeleteManagerModal**. Якщо модальне вікно неактивне, функція повертає **null**.
    - Інтерфейс:
      **AddManager** включає пошук і список менеджерів, форму для додавання нового менеджера з логами, блок редагування обраного менеджера з полями для імені та пароля, кнопками збереження та видалення, а також модальне підтвердження видалення.

        Цей інтерфейс складається з форми входу, де користувач бачить заголовок «Вхід», поле для введення імені, поле для введення пароля, повідомлення про результат авторизації зеленим або червоним кольором та кнопку для підтвердження входу.
      
    ### Manager.tsx
      - Цей компонент Manager відображає робочий екран менеджера, на якому можна переглядати список карток, додавати нові, фільтрувати архів і переглядати деталі вибраної картки. При завантаженні він отримує список усіх карток із сервера та зберігає їх у глобальному стані. 
      - Функції:
        - GetCards: 
          Отримує картки із сервера та зберігає їх у стані або показує.
        - cleanInputs:
          очищає дані форм.
        - choiceFilter:
          вмикає режим фільтрації, ховає картку та додаткові дані і скидає форми.
      - Інтерфейс: 
        Інтерфейс складається з верхнього заголовка, блоку зі списком карток і кнопкою для активації фільтрації, а також правої частини, де залежно від стану показується форма для додавання картки або фільтр з відображенням вибраної картки чи додаткових даних до неї.
    
    ### DocumentCard.tsx
      - Екран показує деталі вибраного документа з   усіма його полями, відображає список додаткових карток, їх організації та дати, а також попередній перегляд PDF документа і короткий зміст.
      - Функції:
        - GetCard:
          **GetCard** отримує дані конкретного документа за його **ID**, оновлює стан форми, **PDF** та додаткових елементів, а також викликає **GetAdditions** для завантаження додаткових карток.
        - GetAdditions:
          Функція **GetAdditions** отримує додаткові картки за **ID** документа і зберігає їх у стані, логуючи помилки у разі невдачі.
      - Інтерфейс:
        Екран відображає деталі документа з усіма полями, включає список додаткових карток як посилання, показує **PDF** документа у вбудованому переглядачі і короткий зміст документа.
